# Source and contribution boundaries

The engine repository contains original implementation code, behavior specifications and invented test fixtures. Keep proprietary material outside it.

- **Implementation sources:** public documentation, reviewed clean behavior specifications and black-box observations.
- **User data:** game assets and configuration files may be read at runtime from a user's own installation. Never commit or attach them.
- **Restricted research:** decompiled source, private SDK material and other proprietary code must not be used as implementation submissions. Researchers should provide distilled behavior notes through maintainer review.
- **Specifications:** describe behavior, formats, measurements and provenance. Do not include copied code, pseudocode, executable addresses or decompiler function names.
- **Review:** maintainers check contributions for copied material and unsupported claims. This is a procedural boundary, not a guarantee of legal clearance.
- **Privacy:** do not publish credentials, home-directory paths or personal data. Use portable example paths.

The original game's assets, binary and decompiled corpus are outside the engine's open-source license.
